API -> Web Service

- A web service is a standardized way for different applications or systems to communicate and share data over the internet
- Web services use standard protocols, typically HTTP/HTTPS, to send and receive messages between clients and servers.
- Platform independent communication
- A web service acts as a mediator between different applications or systems, allowing them to interact with each other over a network. 
- This interaction typically follows a request-response model, where a client sends a request to a server, and the server responds with the necessary data or action.
- Web services are essential for building distributed systems and cloud-based applications in today’s software ecosystem.
- Using webservices two different applications can talk to each other and exchange data

---------------------------------------------------------------------------------------------------------
Characteristics of Web Services/API:

1. Interoperability: Different systems, written in different programming languages, can communicate with each other.
2. Statelessness: Most web services, especially RESTful ones, are stateless, meaning each request from the client to the server is independent.
3. Platform Independence: Web services allow systems on different platforms (Windows, Linux, etc.) to communicate.
4. Accessibility: Web services can be accessed over the internet or a private network.

1. Uniform Interface = Uses standard methods (GET, POST, etc.) for all resources.

. Resource: everything is a resource
. URI: any resource/data can be accessed by a URI (uniform resource identifier)
. HTTP: make explicit use of HTTP methods

2. Client-Server: Separates the user interface from data storage.
3. Stateless = all client-server communications are stateless, Each request contains all information needed to process it.
4. Cacheable = happens at client side. Responses define themselves as cacheable to improve performance
5. Code On Demand = ability to download and execute code on client side

GET (Read): Retrieves data, such as GET /users/123 to fetch specific user details.
POST (Create): Submits new data to create a new resource, such as POST /users.
PUT (Update/Replace): Replaces an entire existing resource, such as PUT /users/123.
DELETE (Remove): Removes a resource, such as DELETE /users/123.
PATCH (Partial Update): Modifies part of a resource, such as PATCH /users/123 to update only an email.

https://www.example.com/index.html (Webpage via HTTPS)
ftp://ftp.example.com/files/document.pdf (File via FTP)
file:///C:/Users/Documents/report.txt (Local file path)
https://github.com (API endpoint)

Uniform Resource Names (URNs): These identify a resource by a persistent name rather than its location.

urn:isbn:978-3-16-148410-0 (A book identified by its ISBN)
urn:ietf:rfc:3986 (A specific Internet standard document)
urn:oasis:names:specification:docbook:dtd:xml:4.1.2 (Software specification)


Uniform Resource Identifier URIs: is a string of characters used to identify a resource by name, location, or both

mailto:info@example.com (An email address identifier)
tel:+1-212-555-1212 (A telephone number)
data:text/plain;base64,SGVsbG8sIFdvcmxkIQ== (A Data URI embedding a small file directly)
geo:37.7749,-122.4194 (Geographic coordinates)
spotify:track:4cOdK2wG6S9999 (A specific track in the Spotify app) 

- All URLs are URIs, but not all URIs are URLs. A URL is a URI that also tells you where the resource is located. 
- A URI is used to identify a resource, whereas a URL is used to locate it
- A URL typically includes a protocol (like https or ftp), a domain name, and a path. A URI can be more abstract and may only include a name (known as a URN), such as urn:isbn:0451450523

---------------------------

Informational responses (100 – 199)
Successful responses (200 – 299)
Redirection messages (300 – 399)

REST Assured:
===============

REST Assured is a popular Java library (DSL) designed to simplify testing and automation of RESTful web services.
It enables testing of GET, POST, PUT, DELETE, and other methods, supporting JSON/XML validation, authentication (OAuth, Basic), and integration with frameworks like JUnit/TestNG/Cucumber/CI-CD. Version 6.0+ supports Java 17+.
 It provides a simple given-when-then


given - pre-requirement (setting initial your request) --> URI, headers, body, auth, parameters
when - actions   (GET, POST, PUT, PATCH ETC)
then - output    (response- status, response header, response body)


We Use 
RestAssured -> class to set base URI as global 
RequestSpecification to initialize the request
given() methods is used to start the pattern, allowing you to add headers, parameters, body
Response is in JSON format so we need to convert it into readable format(string)
